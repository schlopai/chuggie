# Stack review — 2026-08-14

A consolidating read of all three repos: the `tish` toolchain, the `chuggie-engine` engine crates and
packages, and the example corpus. Every number here was checked against the working tree on
2026-08-14; where a previous document's claim no longer holds, that is called out rather than
quietly repeated.

Companions, both still worth reading and neither superseded:

- [`engine-review-2026-08.md`](engine-review-2026-08.md) — a stack read aimed at the RTS question.
- [`engine-roadmap-status.md`](engine-roadmap-status.md) — the 2026-08-13 gap work-list.
- [`perf-rules.md`](perf-rules.md) — the seven frame costs. **Read that one first.**

What this document adds: the toolchain repo (neither companion covers it), a re-verification of the
corpus-health claims (several had gone stale), and one empirical measurement neither had — package
adoption, which turns out to answer the repo's own open question about whether packages are real.

---

## 1. The stack in one page

Four layers, in dependency order:

| layer | where | what it is |
|---|---|---|
| Compiler | `tish/crates/tish_compile`, `tish_native`, `tish` CLI | Target-agnostic. **Emits Rust source as strings**, scaffolds a GBA cargo crate and drives the build. Links no `agb`. |
| Portable runtime | `tish/crates/tish_core`, `tish_builtins` | Language primitives; the `portable` feature is `no_std` + `alloc`. |
| agb facade | `tish/crates/tish_runtime_gba` | The **only** crate that depends on `agb`. Excluded from the workspace, `no_std`, versioned in lockstep with the compiler, linked as a path dep renamed to `tishlang_runtime`. |
| Engine + games | `chuggie-engine/crates`, `packages/`, `examples/` | `tish-agb` (hardware), `tish-gba-game-engine` (entities/AI/physics), the scenepack, 47 tish packages, 155 examples. |

**The hard invariant**: no compiler or core crate may depend on `agb`. It has held.

The generated Rust for a game lands at `<example>/.tish/gba/<name>/src/main.rs`. That file is not an
implementation detail to be ignored — it is the primary debugging artifact, and the perf docs
repeatedly instruct you to read it when a measurement makes no sense. Most of the traps in §4 are
invisible in the tish source and obvious in the emitted Rust.

Extensibility is contributed by the *crate*, not the compiler, which is a genuinely good piece of
design: `cargo:` imports resolve through `package.json`'s `tish.rustDependencies`; a `tish.d.tish`
next to a crate declares typed externs that lower to direct Rust calls; and `tish.schemes.json`
contributes the `asset:` / `sheet*:` / `background:` / `font:` / `strings:` import schemes. The
compiler knows about none of these by name.

## 2. Toolchain state — and one thing that needs attention

**⚠️ The local toolchain is not the released toolchain.** The `tish` checkout is on branch
`gba-stack-frame`, and:

- `git describe` from HEAD gives **v3.7.1**. The latest tag is **v3.8.2**.
- HEAD is **13 commits behind v3.8.2** and carries **8 commits of its own**.
- The tip of those 8 (`ad68e6388`) is *"Revert every codegen change on this branch — core tish must
  stay untouched"* — the branch reverted its own reason for existing.
- `target/release/tish`, the binary every example builds with, was built from that HEAD.

So every measurement currently being taken in `chuggie-engine` is against a compiler that is neither the
released one nor the one the branch was written to test. The `gba-stack-frame` work — lowering
functions over mixed structs, const struct arrays into ROM with indexed field reads, stores into
struct params and globals, a static home for all-numeric struct globals, native struct-param
functions, dead boxed-wrapper elision — is **all reverted**. If the recent struct and stack-frame
findings in this repo's memory were measured here, they were measured without it.

This is the single highest-value item in the document, because it silently invalidates
comparisons. **Recommendation: decide whether that branch is alive; if not, get back onto a tagged
release before the next perf pass.**

**There is no CHANGELOG anywhere in the tish repo.** Release history exists only in tags and commit
subjects. For a project whose consumers are this sensitive to codegen changes — where a lowering fix
moves a measurement 28× — that is a real gap, and it is cheap to close.

Landings worth knowing about (issue numbers from commit subjects):

| | change | effect |
|---|---|---|
| #598 | integers stay integral across the int-domain boundary | up to **28×** on GBA |
| #645 | a promoted array read stays in the integer domain | **63.2 → 0.65** ticks/element |
| #647 | zero-argument fn lowers natively | **553 → 26** ticks |
| #606 | mixed fixed/f64 operand pairs lower natively instead of dropping to boxed ops | |
| #609 | typed-array HOFs lower for `i32[]` receivers | |
| #614 / #615 | numeric-local demotion keyed by (scope, name); typed externs dispatch on exact arity | |
| #618 | `packageOverrides` swaps a module at build time | |
| #656 / #657 | a native tish test runner | |

Still open: `tish/docs/issues/user-fn-call-cost-on-gba.md`. Item 1 is fixed (93.4 → 72.2 ticks per
call); item 2 is partial — *"the ABI exists and works; it does not yet reach the code that motivated
the issue"*; item 3 is untouched. Both were found via `chuggie-engine/examples/bench-grid`, which is the
model to copy: a repro living in the consumer repo, driving a fix in the compiler repo.

Version metadata is misleading and worth a five-minute fix: `Cargo.toml` says `1.0.0`,
`crates/tish/Cargo.toml` says `0.0.0-dev`, `package.json` says `1.0.12`, and the real answer is the
git tag. Three numbers, none of them right.

## 3. The native surface

Five crates, and the split is clean:

| crate | typed externs | role |
|---|---|---|
| `tish-agb` | **98** declares (307 boxed `pub fn` in `lib.rs`) | Hardware: sprites, BG, input, audio, canvas/text, windows, terrain, save, link, FX. |
| `tish-gba-game-engine` | **199** declares | Entities, pools, native AI/behaviour systems, iso grid, movers, fog, rules/RNG. |
| `tish-gba-scenepack` | — | Build-time asset packer (Tiled, fonts, decks, chip, autotile, iso boards, strings, emoji). |
| `tish-agb-sio` | 4 | Link cable. |
| the SRPG data crate (now in the chuggie-tactics repo) | 89 | Generated data tables. |

~28,000 lines of Rust across them.

**A trap worth stating plainly: `tish.d.tish` lists only the *unboxed fast path*.** The full native
surface is `pub fn(args: &[Value])` in `src/lib.rs` — 307 functions in `tish-agb` against 98
declares. A function that exists but is not declared still works; it just costs the boxed path. When
something is unexpectedly slow, check whether it has a declare before concluding the native code is
slow.

The one deliberate omission documented in the tree: `ui_rect`'s **5-argument outline form is
intentionally un-declared**, because both arities lower to one unsuffixed symbol. That is a
compiler bug being routed around in a declaration file, and it should be written into the issue
tracker rather than living as a comment.

## 4. Language traps, sorted by whether they are fixable

The seven frame costs are in [`perf-rules.md`](perf-rules.md) and are not repeated here. What
follows is the trap list, split by the thing the previous documents never separated: **which of
these are compiler bugs awaiting a fix, and which are permanent properties of an ARM7TDMI.**

### Compiler bugs / missing lowerings — these can go away

| trap | today |
|---|---|
| An untyped scalar is **soft-float**. `const X = 5` *and* bare `let X = 5` become a thread-local `Cell<f64>`. | Write `let X: i32 = 5`. Rule 1 of perf-rules; costs ~20% of a frame; `scripts/const_to_let.py` finds them. |
| An untyped array is **28 bytes per element**. `const XS: i32[]` is *still* a boxed `Value::Array`. | Only `let XS: i32[]` is a `Vec<i32>`. One package leaked 46 KB to this. |
| **`a * b` on i32 locals is still soft-float** — multiply does not follow add/subtract's typed lowering. | Use `Math.imul`. A masked index additionally needs a power-of-two length *and* the mask written at the index site. |
| A **typed struct assignment copies**. `let s: Ship = SHIP` snapshots; later writes to `s` are discarded. | Go through `SHIP.field`. |
| **A typed fn still emits a boxed closure** — the compiler emits both a native fn *and* a `Value::native`. Typing changed one measured stack frame by zero bytes. | Typing helps call *sites*, not the definition's footprint. |
| **`arr.length = 0` silently no-ops** on a typed array. | Use a pop loop. |
| **A missing imported name builds**, then throws at runtime — a black screen, not a compile error. | Nothing catches this today. |
| **tish does not check call arity.** | `scripts/arity_check.py` exists because of it. A dropped comma in a 10-argument authoring call is a zero-damage move, not an error. |

That list is the compiler backlog, and it is worth filing as such. Items 1, 2 and 3 alone account
for most of the perf folklore in this repo.

### Permanent — the hardware is not going to change

- **No divide instruction.** Every `%` and `/` is a software call. `motionRead`'s one `%` cost 1,400
  of 4,389 ticks. Power-of-two sizes and masks; `>>` for constant division; countdown counters
  instead of `frame % 60`.
- **Sprite VRAM is 32 KB and panics rather than degrading** — `SpriteFull`, from inside agb, minutes
  into play, on no particular frame. `sprite_set_visible(h, 0)` does **not** free the Object.
- **16 sprite palette banks**, hard.
- **`/` is not reliably truncating** in tish — write `((a * b) / c) | 0` where a division genuinely
  belongs.
- **No `undefined`** (a missing value is `null`) and **no loose equality** (`someBool === 1` is
  `false`).

### Build behaviour

- **Builds are nondeterministic** — the same source emits Rust in a different *order* every build (a
  `HashMap` in codegen). Diffing two builds of unchanged source is not a signal.
- **`tish build` caches packages.** Editing `packages/*.tish` may not recompile; `rm -rf .tish`.
- **⚠️ `TISH_FAST_NATIVE_BUILD` exits 0 on a failed GBA compile** and leaves the *previous* `.gba` in
  place, so you debug a stale ROM. This one deserves to be a hard error, not a footgun.

## 5. The `run()` stack ceiling

The largest single class of "impossible" bug in this repo's history, and the one most likely to bite
the next large module:

**`run()`'s frame eats ~27 KB of a 29 KB stack.** Module-level functions become closures that live
in `run()`'s frame for the whole program, so a game with several hundred of them boots and then
faults somewhere unrelated — and the fault **relocates** when you perturb the code, which is exactly
what makes it look impossible.

The fix that works is structural, not organisational: **wrap a module's functions in a factory** so
their closures leave `run()`'s frame. Moving code between *files* changes nothing; closure
*lifetime* is the variable. This landed for `packages/battle.tish` and for the large SRPG example's shell and took
the battle from "resets the ROM" to zero faults.

**The rule for any new large module is to adopt the factory shape from the first commit**, rather
than discovering the ceiling at 600 closures. This is cheap up front and extremely expensive to
retrofit.

## 6. Packages vs examples — the ratio, measured

`engine-roadmap-status.md` proposed a test: *a genre is proven when someone else's example can be
built on the package without touching it.* That test has now been run, by counting importers of
every package across the whole corpus.

**47 packages, 155 examples.** Adoption:

| importers | packages | which |
|---|---|---|
| 10+ | 7 | `engine` (56), `iso` (37), `isodemo` (32), `ui` (22), `rng` (16), `dialog` (16), `chipsfx` (13), `deck` (11), the SRPG presentation package (10) |
| 3–9 | 11 | `scene`, `cutscene`, `pool`, `motion`, `feel`, `title`, `shop`, `shmup`, `platformer`, `mode7`, `link`, `iso_actors`, `fighter` |
| **2** | 11 | `topdown`, `search`, `save`, `rhythm`, `prefs`, `cutscene-core`, `clansave`, `buildid`, `beatemup` |
| **1** | 15 | `rts`, `replay`, `party`, `parallax`, `music`, `microgame`, `menu`, `kart`, `grid`, `fpview`, `flags`, `dungeon`, `battle` |
| **0** | 3 | `fx`, `memdebug`, `scene_hooks` |

**26 of 47 packages have two importers or fewer, and 15 have exactly one.** A package with one
importer is not a package; it is that example's source file living in a shared directory. The
structural test has been run and the answer is: **roughly a third of the packages layer is not yet
proven.**

Two caveats that soften it slightly, and one that does not:

- `fx` and `pool` are *constants-only* modules (`FXP_*`, `POOL_*`) mirroring native enums; zero
  function cost, and low adoption is expected.
- Several one-importer packages are **days old** (`flags`, `replay`, `fpview`, `dungeon`,
  `microgame` all landed 2026-08-13/14). Their first consumer is their acceptance test. They have
  not had time to get a second.
- But `menu`, `party`, `kart`, `grid`, `parallax`, `battle`, `rts` are not new, and they still have
  one consumer each.

The corollary is not "delete them". It is that **the cheapest high-value work in the repo is a
second consumer for an existing package, not a 48th package.** `ringside` (below) is deliberately
built the other way round — the package is written *for* the example, but with a table format
designed so the second boxer is data, not code.

`scene_hooks` at zero importers is worth a look specifically: it is described as the hub shared by
engine/ui/dialog, so zero is either a dead module or a broken wiring.

### Still open from the roadmap

- ❌ **Dungeon-logic extraction.** Written twice already (in the two topdown RPG ports, since moved to their own repo) and never
  extracted. ⚠️ The obvious name is now **taken** — `packages/dungeon.tish` is the BSP generator, so
  this needs `dungeonlogic` or `keylock`.
- ❌ **Board/card framework.** `solitaire` and the card-battle SRPG demo are still two one-offs.

## 7. The one genuinely open gap: audio

Six of the seven cross-cutting gaps from the 2026-08-13 plan are closed. Audio is the survivor, and
it is thinner than the roadmap's own summary suggests:

**220 lines across all three audio packages** — `deck.tish` 40, `chipsfx.tish` 119, `music.tish` 61.
Ducking (`audio_duck`) and adaptive intensity (`deck_set_intensity`, `MI_CALM…PEAK`) landed. What is
still missing:

- **No mixer.** Sounds do not layer; they take a channel.
- **No positional or panned SFX.**
- **No music state machine** beyond the intensity scalar.

The consequence is concrete rather than theoretical, and `ringside` is a clean demonstration of it:
four PSG channels, ch1 reserved for melody, ch2 tonal, ch4 percussive. A continuous crowd bed needs
ch4 permanently — and ch4 is the punch channel. So the choice is a crowd that ducks audibly several
times a second, or punches masked by crowd noise, or no crowd bed at all. The demo takes the third
option and fires **crowd swells on events** instead, which is defensible game design and also
straightforwardly a workaround.

**A mixer is what unblocks ambience in every genre at once.** It is the last system-shaped hole, and
it is the one thing on this list that no example can route around.

## 9. Process artifacts worth protecting

These are the repo's real assets, more than any individual package:

- **The de-risk spike pattern** — nine tiny ROMs, one per load-bearing assumption, retired
  *before* the 6,130-line topdown RPG port was written. Nine spikes cost far less than one large game
  discovering its ceiling at the end. This is the most valuable process artifact in the repo and it
  should be the default for anything over ~1,000 lines.
- **`verify.sh` + `scripts/verify_common.sh`** — and specifically the four checks that nothing else
  catches: `assert_typed_scalars` (the perf-rules §1 regression gate — without it the next edit
  silently undoes the sweep), `arity_check.py`, `soak_rom` **with an input schedule** (attract mode
  never presses a button, so a soak without one never executes the player's code path), and
  `shot_check.py`, which refuses to report pixel metrics off a dead ROM — the trap that once made a
  constant crash-screen reading look like a stable measurement.
- **Headless screenshots** (`scripts/screenshot.sh` via libmgba) — no emulator window, no macOS
  Screen Recording permission, takes a key schedule. This is what makes any of the above automatable.
- **`scripts/const_to_let.py`** — the tool for the single most expensive language trap.
- **Generated everything** — `examples/README.md`, asset sheets, `frames.tish`, `buildid.tish`,
  generated data tables. The house rule that a derived file carries a `GENERATED — do not edit` banner is
  consistently followed and worth keeping.

The measurement discipline is also worth restating because it is counterintuitive: **only compare
builds whose `log()` line is byte-identical.** On `sunny-land`, changing only which fields were
concatenated inside the `log()` call moved a measured `step_ticks(1)` from 1,466 to 2,441 — a 66%
swing, pure instrumentation, in a phase the logging did not even run in.

## 10. Recommendations, ranked by value ÷ cost

1. **Resolve the `gba-stack-frame` branch** (§2). The toolchain building every ROM here is 13
   commits behind its own latest release, on a branch whose tip reverts its own work. Until that is
   settled, no perf comparison in this repo means what it appears to mean. *Cost: a decision.*
2. **Add a CHANGELOG to the tish repo** (§2). Consumers of this compiler are unusually sensitive to
   codegen changes; tags and commit subjects are not enough. *Cost: an afternoon.*
3. **Make `TISH_FAST_NATIVE_BUILD` fail loudly** (§4). Exiting 0 on a failed compile and leaving a
   stale ROM is the worst failure mode a build tool can have. *Cost: small.*
4. **File the §4 compiler-bug list as issues.** Untyped-scalar soft-float, boxed typed arrays, and
   `a * b` not following typed lowering account for most of this repo's perf folklore. They are
   currently documented as *rules for authors* when they are really *bugs for the compiler*.
   *Cost: an hour of writing; large payoff.*
5. **The stale-ROM sweep** (§8) — 24 SRPG example directories plus six others carry a dead ROM from a
   rename. *Cost: one `find`.*
6. **Second consumers, not new packages** (§6). 15 packages have exactly one importer. The cheapest
   way to make the packages layer real is to build the next example *on* one.
7. **The audio mixer** (§7). The last system-shaped hole, and the only one no example can route
   around.
8. **Extract the dungeon logic** (§6) under a new name — `dungeon` is taken. Written twice,
   never extracted, and it is the roadmap's own cheapest remaining test of whether packages are real.
9. **`asteroids` needs a `preview.png`**; `p0-spike` should move out of `examples/`. *Cost:
   minutes.*

## Addendum: what this review produced

The genre observation that closed the last review — *the whole catalogue is side-view, top-down or
isometric, and nothing renders **into** the screen* — produced `packages/fpview.tish` and
`examples/crawler`. It has a second answer, and it now exists: **`examples/ringside`** +
**`packages/boxing.tish`**, an over-the-shoulder boxing game, shipped alongside this document.

It is the same camera family and a completely different model. A first-person crawler renders into
the screen and moves on a grid; a boxing game renders into the screen and **does not move at all**.
There is no locomotion axis, no facing, no hitbox geometry — the entire game is a timeline, and a
punch resolves by comparing a table column against the defender's current stance. It is the first
example in the corpus whose core loop is pure reaction timing.

It is also deliberately a **second consumer of `packages/feel.tish`**, which had exactly one. That is
recommendation 6 (§6) applied to this document's own output rather than only recommended, and it
worked as advertised — the seam only a second consumer can find showed up immediately:

- **feel's *kinds* are generic; its *presets* are not, and cannot be extended.** The seven presets
  are named for card events (PLACE, DESTROY, BUFF, LANE, ILLEGAL, VICTORY, DEFEAT) but decompose into
  generic rows, so ringside matched them **by effect shape** and changed nothing. What is genuinely
  missing is a `feelDefPreset` — a consumer can reuse the seven rows-ranges or nothing.
- **`FB_BURST` assumes a flat background.** `feelBurstDraw(i, bg)` erases by repainting each radius
  in a caller-supplied solid colour, which no drawn background can supply. `FB_FLASH` ports fine
  because feel leaves *that* erase to the caller, who can use transparent `ui_clear_rect`. Two
  neighbouring kinds, one portable and one not.
- **⚠️ `feelTick()` walks all six slots every call, and that is ~1,100 ticks in an action frame.**
  Free in a turn-based card frame; a quarter of the budget on top of a sprite composite and two state
  machines. It put **11 of 23 windows over budget in attract mode with the pad untouched**. And
  `feelPlay` on a two-row preset cost ~1,000 ticks more than the two calls it replaced. The fix is
  feel's own argument turned into a rule: **the player is for composing many effects, not two** — step
  it only while something is live, and send frequent two-effect responses to `feelBump` /
  `feelPlaySfx` directly. That took it to 0 of 23.

**This generalises past feel**: a package written against one genre's frame budget carries that
budget as an unstated assumption. Worth checking on the next package that gets a second consumer.

Three further findings came out of building the demo itself:

1. **A new sprite-VRAM failure mode, and it is an *animation* problem.** agb frees tile VRAM only at
   commit, so a frame that re-points a cell transiently holds **both** the old tiles and the new
   ones. Six 64x64 cells flipping on the same frame is 12 KB of transient on top of 10 KB steady —
   and it panicked with `SpriteFull` after **two seconds of standing still**, on a frame where
   logging proved both state machines healthy. `perf-rules.md` §4 covers sprite VRAM as a *budget*
   problem; this is the same ceiling reached by *churn*, which the rule as written does not warn
   about. Two fixes: stagger the animation so no two cells change on one frame, and stop paying for
   pixels below the bottom of the screen (halving two over-tall bands took 17.9 KB to 10 KB).
   **Worth adding to `perf-rules.md` §4 as a second paragraph.**
2. **`key_pressed` takes an ORDINAL, not a bitmask** — `0=A 1=B 2=Select 3=Start 4=L 5=R 6=Up
   7=Down 8=Left 9=Right`. Passing the GBA's real KEYINPUT bits compiles, runs, and silently reads
   the wrong button or none, because `button_of` returns `None` past 9 and `None` reads as
   "not pressed". This is the §4 "a missing name builds" family, one level down: not a missing
   name, a *valid* call with meaningless arguments. Nothing warns.
3. **`ui_rect` takes 24-bit `0xRRGGBB`, not the GBA's native BGR15.** Hardware colour values paint
   the wrong hue rather than erroring, which reads as a palette bug.

It also, deliberately, produces a concrete argument for recommendation 7 (§7): with four PSG
channels and no mixer, a continuous crowd bed would need ch4 permanently, and ch4 is the punch
channel. The demo fires crowd swells on events instead. That is defensible game feel and also the
only option available.
